==============================================================================
IDEAS WORTH BUILDING
Priz's Islands Hub / Islands Auto Builder / Duvome
==============================================================================

Grouped by area. Ordered roughly by how much they pay back for the work.
Anything marked [BIG] is a multi-session job; everything else is an evening.


------------------------------------------------------------------------------
1. UI FRAMEWORK (DL.lua)
------------------------------------------------------------------------------

* Command palette. Ctrl+K opens a search box over the window; type "snipe",
  "deposit", "hollow" and it lists matching controls from EVERY tab with the
  tab name beside them. Enter jumps there and flashes the row. With this many
  sections it is faster than remembering which tab a thing lives on, and it
  costs almost nothing because every element already registers a Name.

* Favourites / pinned controls. Right-click any row -> "Pin". Pinned rows are
  cloned into a Favourites section at the top of the first tab. Most sessions
  use six controls out of two hundred.

* Undo stack for destructive actions. Demolish, Empty Vendings, Nuke, Delete
  Shop all fire instantly. Keep the last N actions with an Undo button in the
  notification itself ("Emptied 42 vendings  [Undo]"). Where a true undo is
  impossible, at least a "hold to confirm" ring on the button.

* Search inside a tab. A one-line filter at the top of each tab that hides
  non-matching rows. Simpler than the palette and useful on its own.

* Element states: disabled + busy. Right now a button that cannot work still
  looks clickable, and one that is working looks idle. Add :SetEnabled(false)
  (dimmed, no hover, tooltip explains why) and an in-button spinner while a
  callback runs. Half the "is it broken?" moments are this.

* Inline validation on textboxes. Red stroke + reason under the field when the
  input does not parse, instead of a notification that scrolls away.

* Keybind conflict detection. If two features claim the same key, show both
  names and refuse the second bind. Silent shadowing is very hard to debug.

* Keybind cheat sheet overlay. Hold a key to see every active bind laid out
  as a card. Reads straight out of the existing keybind registry.

* Per-tab config profiles. Configs are global today. Let a profile be saved
  as "PvP", "Farming", "Shop day" and swapped from the topbar in one click.

* Config diff before load. When loading a saved config show what will change
  ("Sniper: off -> on, Max Price: 1k -> 50k") instead of applying blind.

* Notification centre. Notifications vanish. Keep the last 50 in a panel with
  timestamps, so "did that actually fire?" is answerable after the fact.

* Notification grouping. 40 identical "Deposited x1" toasts should collapse
  into one that counts up. Cheap, and it stops the screen filling.

* Panel docking + memory. Panels remember which side they were on and whether
  they were open, per profile. Right now every session starts from scratch.

* Panel tabs. When two panels are open on the same side, stack them as tabs in
  one frame instead of replacing each other.

* Window snap sizes. Double-click the topbar to cycle compact / normal / tall.
  Compact (just the sidebar + one column) is genuinely useful on a laptop.

* Opacity slider in Settings, live. Glass is a constant right now; expose it
  with a slider and a "click-through when unfocused" option.

* Colour-blind safe accent check. The theme picker can warn when Text vs
  TextDark contrast falls below a readable ratio.

* Sound design, optional and off by default. A soft click on toggle, a
  different one on error. Surprisingly big effect on how finished it feels.


------------------------------------------------------------------------------
2. ISLANDS HUB - FEATURES (PIHD.lua)
------------------------------------------------------------------------------

VENDINGS / ECONOMY

* Vending profit dashboard. [BIG] Track every sale the client sees over a
  session: coins/hour, best-selling item, dead stock that has not moved in an
  hour. This is the single most useful thing a shop owner could have and none
  of the data needs a server call - it is all already being polled.

* Price history graph. Store the price seen for each item each scan and draw a
  sparkline in the price guide. "Is 40k high?" is unanswerable today.

* Undercut assistant. Given a target competitor shop, set your prices to N%
  below theirs across the board, with a floor so you never sell at a loss.

* Restock priority queue. Instead of restocking everything equally, restock
  what actually sold first. Falls straight out of the sales tracker.

* Stock alerts. Notify when any vending drops below X, with a keybind to jump
  to it. Optional: only alert on items above a value threshold.

* Bulk price templates. Save a whole shop's price list as a named template and
  apply it to another island in one click. Half of this exists in the saved
  shops already.

* Vending heatmap ESP. Colour vendings by coin balance or by how stale their
  stock is, rather than one flat highlight colour.

* Sniper: per-item max price. Today there is one global max. A table of
  item -> max price is what actually makes a sniper usable.

* Sniper: blacklist. Items to never buy no matter how cheap.

* Sniper: dry run mode. Log what it WOULD have bought for five minutes before
  trusting it with coins.

SCANNERS / INFO

* Scanner scheduling. Run selected scanners every N minutes and only notify on
  change ("blocks: +240 since last scan").

* Export scan results. Copy to clipboard as CSV/JSON. People want this in
  spreadsheets, and clipboard already works for configs.

* Diff two scans. Take a snapshot, do something, take another, show what
  changed. Excellent for figuring out what a game update altered.

* Island value estimator. Sum blocks x price-guide value for a rough net
  worth number. Fun, shareable, and drives use of the price guide.

* Player watchlist done properly. Notify when a named player joins, with their
  island code and last-seen time.

QUALITY OF LIFE

* Auto-reconnect / rejoin on kick, preserving which toggles were on.

* Anti-AFK that is not just a jiggle: rotate camera slightly, vary the delay,
  and pause while you are actually inputting.

* Panic key. One bind that turns off every automation at once, closes panels
  and hides the UI. Insurance.

* Action queue with a visible list. Instead of firing 200 deposits into the
  void, show a queue with progress, pause and cancel. Makes long jobs safe.

* Rate limiter with a dial. One global "requests per second" control that
  every automation respects, so throttling is tuned in one place.

* Session summary on close. "This session: 4.2M coins, 812 items deposited,
  3 shops restocked." Reads from the stats already collected.


------------------------------------------------------------------------------
3. AUTO BUILDER (IAB.lua)
------------------------------------------------------------------------------

* Build queue + resume. [BIG] Large builds die on disconnect. Persist progress
  (which block index was last placed) and offer "resume build" on next load.
  For 80k-block builds this is the difference between usable and not.

* Material shopping list. Before building, show exactly how many of each block
  the build needs vs how many you have, with the shortfall highlighted.

* Ghost preview with a slider. Scrub through build order to see it assemble;
  useful for checking a converted model before committing.

* Layer-by-layer build mode. Build one Y level at a time with a pause between,
  so you can stop it mid-way and inspect.

* Region select -> save as build. Drag-select an area in-game and export it as
  a build JSON. Closes the loop: the toolkit can currently place builds but
  not capture them.

* Build diff / repair. Compare the build file to what is actually placed and
  place only the missing blocks. Perfect after a partial or interrupted run.

* Mirror / rotate / array before placing. Rotate 90/180/270, mirror on X or Z,
  and repeat N times with an offset - all on the preview, before committing.

* Palette remap UI. Swap every stone block for andesite across a whole build
  with a two-column mapping table. Currently a converter-level decision that
  cannot be changed after import.

* Auto-scaffold. For builds with floating sections, generate temporary support
  blocks and remove them afterwards.

* Cost estimate in coins, using the price guide, before you start.

* Model converter: LOD preview. Show the same model at 5k / 20k / 80k blocks
  side by side so the budget choice is informed rather than guessed.

* Schematic converter: block substitution report. After converting, list which
  Minecraft blocks had no good Islands match and what they became. Right now
  a bad match is only discovered by looking at the finished build.

* Schematic converter: crop / trim tools. Cut a schematic to a bounding box or
  strip the bottom N layers (dirt foundations) before converting.


------------------------------------------------------------------------------
4. ORGANISATION / PANELS
------------------------------------------------------------------------------

* Dashboard tab. One screen: coins, island value, active automations with
  on/off, last five notifications, session timer. The tab you leave open.

* Move every "danger" control into one Advanced panel behind a toggle, so the
  main columns hold only what is used daily.

* Collapse groups by default, remember which were expanded per profile.

* Consistent section order across tabs: status first, controls second,
  destructive last. Right now order varies by tab.

* Split the settings gear from per-element options. Global settings (theme,
  glass, keybinds, rate limit) belong in one place; per-element options belong
  on the element. Today both live behind similar-looking gears.

* Contextual empty states. "No vendings found - are you on your island?" beats
  an empty dropdown reading "No items".

* Tooltips that say the consequence, not the mechanism. "Empties every
  matching vending - this cannot be undone" rather than "Calls empty on
  targets".


------------------------------------------------------------------------------
5. RELIABILITY / DEV
------------------------------------------------------------------------------

* Version + changelog in the About panel, fetched from the repo, with a
  "new since you last ran it" marker. The build stamp already proves whether
  the CDN served fresh code; a changelog makes that useful to the user too.

* Self-test button. Runs a set of assertions (network paths exist, remotes
  resolve, palette names all present) and reports what is broken. Every game
  update breaks something; this finds it in five seconds instead of an hour.

* Error capture. Wrap callbacks so a Lua error becomes a notification with the
  feature name and a "copy error" button, instead of a silent dead button.

* Feature flags fetched from the repo, so a broken feature can be disabled
  remotely after a game update without everyone re-executing.

* Performance HUD. Worst-frame time and how many connections are live. Handy
  for catching the automation that is quietly eating the frame budget.

* Split DL.lua. [BIG] It is one very large file doing themes, elements,
  panels, key system and notifications. Splitting into modules loaded from the
  repo would make everything after it cheaper to change.

* A stub-based test harness in the repo. The pattern already used ad hoc this
  session - extract a module, run it under the luau CLI with fake Roblox
  globals - should be a committed script that runs over the palette, the
  block map and the converters on every change.
